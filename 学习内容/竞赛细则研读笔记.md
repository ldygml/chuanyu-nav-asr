## 二、初赛提交规范（predictions.jsonl）

- 格式：`{"id": "UUID", "text": "转录文本"}`，UTF-8 无 BOM，JSONL
- id = 音频文件名（UUID，不含 .wav）
- 每个测试样本 id 恰好一行，仅允许 id/text 两字段
- 重复 id、未知 id、非法 JSON、非 UTF-8 → 格式错误
- 文本提交前须用官方 normalize.py 规范化（只保留汉字/英文/数字）
- 提交次数：每日 ≤3 次，全程 ≤20 次

---

## 三、评测指标与排名

| 顺位 | 指标 | 方向 |
|---|---|---|
| 1 | CER（规范化后字符编辑距离错误率） | 越低越优（主指标） |
| 2 | RTF（端到端运行时间 / 音频总时长） | 越低越优 |
| 3 | 峰值 GPU 显存 | 越低越优 |
| 4 | 提交时间 | 越早越优 |

```
CER = (S + D + I) / max(1, N_ref_chars)
```

- 决赛入围：Top N 获奖候选须 3 次独立复跑，CER 需在容差内一致
- 初赛不测 RTF/显存；决赛 RTF 从 run.sh 启动到退出全程计时（含模型加载）

## 五、决赛 run.sh 硬性要求

- 唯一入口，解析 `--input_manifest` / `--output_path` / `--device` 三参数
- 不得假设固定绝对路径；写入 --output_path 指定位置
- 成功退出码 0，失败非 0
- 禁联网、禁后台驻留、禁读非挂载目录
- submission.yaml 需申报：权重清单 SHA-256、外部数据/模型来源与许可证、后处理声明

## 六、合规红线（重点！）

### 数据使用（细则 2.3）

- ✅ 可用：官方训练/开发数据、赛前明确允许的公开数据、预训练模型、开源工具
- ✅ 用外部资源须如实申报（名称、版本、来源、许可证、使用方式）
- ❌ **不得使用由测试集直接衍生的任何数据、模型、词典与规则**
- ❌ 测试音频不得用于人工转录、人工校对、外部服务转写、**构建答案映射表**、训练/微调

### 禁止行为（细则 7.2）

- 联网下载模型 / 调用云端 ASR·LLM·API / 上传测试音频或结果
- 按测试文件名或音频指纹建立答案映射
- 使用提前获知的测试文本、录音、元数据
- 使用未申报的数据/模型/权重
- 通过输出大小、运行时间、崩溃信息、高频提交探测隐藏集分布

### 违规后果

版本无效 → 情节严重取消参赛资格/成绩/获奖资格。组委会保留运行日志、哈希与审计记录。

## 七、对本项目的启示

1. **human_correct.md 热词词典是合规风险点**：它是人工校对测试集预测产出的"错误→正确"映射，落在"测试集派生词典"与"人工校对"两条红线上。A 榜提交应使用模型纯推理结果。
2. 若后续想合法用后处理：热词须来自**训练集/公开资料**（地名库、导航 POI 库），并保留来源与制作过程说明以备申报。
3. 决赛提交前要检查 submission.yaml 的 external_resources 申报与权重 SHA-256。
4. 初赛提交前自检清单：BOM、行数=3461、id 集合与 TEST 目录一致、字段仅 id/text、空文本、规范化。
