## 二、热词后处理迭代（4 轮收敛）

### 第 1 轮：词库更新后全量音素替换

用户更新 human_correct.md 词库（2106 行 → 后来 2102 行）后重跑 asr-hotword PhonemeCorrector。

**结果**：1851 句被改。dev 105 句验证 CER 从 2.37% 恶化到 4.96% —— 音素双向模糊匹配大量误伤。

### 第 2 轮：词库精确判据（改错的恢复，改对的保持）

规则：只保留 wrong 侧**精确等于**词库条目的替换，音素变体全部恢复。

**结果**：878 kept / 2025 reverted。dev CER 3.34%（好于音素版 4.96%，仍差于基线 2.37%）。

### 第 3 轮：子串误伤防护

用户点名三类残留误伤：`没耽误→没耽搁误`、`自驾去→自驾车去`、`久曲路→旧曲路`。

防护规则（hotword_fix.py）：
1. **变长替换邻接汉字 → 恢复**（拦截插入型误伤：`没耽→没耽搁` 顶出右邻"误"字）
2. **手动例外名单 REVERT_SET**：`久曲路→旧曲路`、`经点→景点`（dev 10 次命中 +0.232pp 实证伤害）
3. 顺带修复 rfind 重复匹配 bug：用 `last_end` 游标 + `rfind(w, 0, last_end)` 防止替换产物中的子串被二次替换

**结果**：827 kept。三处点名误伤全部清零（没耽搁误 0 / 自驾车去 0 / 旧曲路 0；"沿途景点"是原文固有正确内容，未动）。

### 第 4 轮：服务器化（最终版）

用户更新词库至 2102 行后，词典 + hotword_fix.py 上传服务器（/tmp/human_correct.md、/tmp/hotword_fix.py），md5 与本地核对一致。

**最终统计**：3461 句，686 句修改，812 kept / 2042 reverted。
- kept Top3：途径点→途经点(16)、鲁能新城→鲁能星城(6)、建格县→剑阁县(5)
- reverted Top3：司机→实际(470)、小区→校区(269)、分钟→1分钟(187)

## 三、完整推理流程重建与复现验证

### 流程（官方 run.sh 三步骤）

| 步骤 | 脚本 | 作用 |
|---|---|---|
| 转换语音 | src/prepare_manifest_data.py | wav → 40维 MFCC ark + data.list（torchaudio MFCC: n_mfcc=40, n_fft=512, hop=160） |
| 推理 | src/infer.py（hydra, decoding.type=viterbi） | nav80k_cont greedy → infer.log（HYPO 行 + IDX） |
| 后处理 | src/make_predictions.py | 按 IDX 排序对齐 + 去 `<unk>` → predictions.jsonl |

### 执行方式（不新建脚本，直接复用服务器现成 run.sh）

1. 备份决赛权重：`cp weights/model.pt /tmp/model.pt.final.bak`
2. 换入 80k_cont：`cp /Save/checkpoints_nav80k_cont/checkpoint_best.pt weights/model.pt`
3. 跑 `bash run.sh --input_manifest /Save/初赛_test_manifest.jsonl --output_path /Save/predictions_nav80k_cont_greedy_v2.jsonl`
4. 跑完恢复决赛权重

**复现结果**：v2 与旧版 3461/3461 逐字一致 ✓（流程可复现、确定性）

## 四、ASR + 热词一体化 Pipeline

用户要求把 ASR 与热词修正整合为单一 pipeline。

**产出**：`/root/asr-competition/run_pipeline.sh`

```

  ├─ Step 1/4: prepare_manifest_data.py   wav → MFCC + data.list
```
