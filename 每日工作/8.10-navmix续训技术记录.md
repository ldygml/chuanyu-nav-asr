## 二、训练启动过程（5 次尝试）

### 尝试 1：直接调 hydra_train.py + fairseq 默认 config

```bash
python fairseq_cli/hydra_train.py \
    model.w2v_path=... task.data=... checkpoint.restore_file=... \
    checkpoint.reset_lr_scheduler=true checkpoint.reset_optimizer=true ...
```

**错误**: `Could not override 'model.w2v_path'. Key 'w2v_path' is not in struct`

**原因**: fairseq `config/config.yaml` 里 `model: null`、`task: null`。OmegaConf struct mode 下 null 节点不能设子键。

### 尝试 2：加 `+` 前缀

```bash
+model.w2v_path=... +optimizer._name=adam ...
```

**错误**: `Could not add 'model=wav2vec_ctc'. 'model' is already in the defaults list.`

**原因**: `+` 是"追加到 defaults"，但 model 已在 defaults 中（即使值为 null）。应改用 override 语法。

### 尝试 3：显式指定 model name

```bash
model=wav2vec_ctc task=spec_finetuning ...
```

**错误**: `Could not load task/spec_finetuning. Available options: audio_finetuning, ...`

**原因**: `spec_finetuning` 注册在用户模块 `data2vec_dialect` 里，Hydra ConfigStore 在加载 user_dir 之前就完成了 task group 解析。用户模块的 task/model 不在 Hydra ConfigStore 中。

### 尝试 4：正确的 config 文件

找到用户模块自己的 config YAML:
`/root/asr-competition/ASR/data2vec_dialect/config/v2_dialect_asr/base_audio_finetune_140h.yaml`

```yaml
model:
  _name: wav2vec_ctc    # ← 预填了 schema name
  w2v_path: ???
task:
  _name: spec_finetuning  # ← 预填了
optimizer:
  _name: adam
lr_scheduler:
  _name: tri_stage
```

用这个 config + `--config-dir config/v2_dialect_asr --config-name base_audio_finetune_140h` 启动 —— model 和 task 的 struct mode 问题解决了。

但遇到新错误: `ValueError: --finetune-from-model can not be set together with either --reset-optimizer or reset_lr_scheduler`

### 尝试 5：去掉 reset_* + 修复数据路径

- 去掉 `reset_lr_scheduler` 和 `reset_optimizer`（`finetune_from_model` 已自动处理）
- 修复数据路径（见第三节）
- 创建 tsv 软链接（见第三节）
- ✅ **成功启动**

## 四、最终训练配置

### 启动目录
`/root/asr-competition/ASR/data2vec_dialect/`（config 路径是相对于此目录的）

### 完整命令

```bash
cd /root/asr-competition/ASR/data2vec_dialect
export PYTHONPATH=/root/asr-competition/fairseq:/root/asr-competition/ASR/data2vec_dialect:$PYTHONPATH

python /root/asr-competition/fairseq/fairseq_cli/hydra_train.py \
    --config-dir config/v2_dialect_asr \
    --config-name base_audio_finetune_140h \
    common.user_dir=/root/asr-competition/ASR/data2vec_dialect \
    common.fp16=false \
    common.seed=777 \
    common.log_format=json \
    common.log_interval=200 \
    model.w2v_path=/root/asr-competition/model_checkpoints/kespeech_encoder.pt \
    model.freeze_finetune_updates=0 \
    task.data=/root/asr-competition/train_data \
    +task.target_dictionary=/root/asr-competition/model_checkpoints \
    checkpoint.save_dir=/Save/checkpoints_nav_mix_cont \
    checkpoint.finetune_from_model=/Save/checkpoints_nav_mix/checkpoint_best.pt \
    checkpoint.keep_best_checkpoints=-1 \
    dataset.max_tokens=50000 \
    dataset.max_tokens_valid=50000 \
    optimization.max_update=40000 \
    'optimization.update_freq=[1]' \
    'optimization.lr=[5e-06]' \
    > /Save/checkpoints_nav_mix_cont/train.log 2>&1 &
```

### 关键参数解析

| 参数 | 值 | 说明 |
|------|-----|------|
| `finetune_from_model` | navmix checkpoint_best.pt | 加载完整权重 + **自动重置** optimizer/lr_scheduler |
| `w2v_path` | kespeech_encoder.pt | encoder 基础权重（被 finetune_from_model 覆盖） |
| `lr` | 5e-06 | 超低 LR，保护已有知识 |
| `max_update` | 40000 | 总步数 |
| `freeze_finetune_updates` | 0 | 不冻结 |
| `fp16` | false | FP32 全精度 |

### Config YAML 提供的默认值

以下参数**不需要在命令行 override**，已由 `base_audio_finetune_140h.yaml` 预设:

- `optimizer._name=adam`, `adam_betas=(0.9,0.98)`, `adam_eps=1e-08`
- `lr_scheduler._name=tri_stage`, `phase_ratio=[0.1, 0.4, 0.5]`, `final_lr_scale=0.05`
- `criterion._name=ctc`, `zero_infinity=true`
- `checkpoint.no_epoch_checkpoints=true`, `best_checkpoint_metric=uer`
- `dataset.num_workers=6`
- `distributed_training.ddp_backend=legacy_ddp`, `find_unused_parameters=true`

## 六、关键踩坑总结

### fairseq Hydra 训练启动的正确姿势

1. **不要用 fairseq 默认 config.yaml**——`model: null` 导致所有 override 失败
2. **用户模块的 config YAML 是必须的**——预填了 `_name` 字段才能通过 struct mode
3. **`--config-dir` 和 `--config-name` 一起用**——前者指向 YAML 所在目录（相对于 CWD），后者是 YAML 文件名
4. **`finetune_from_model` ≠ `restore_file`**：
   - `finetune_from_model`: 新训练，加载权重，重置 optimizer/scheduler
   - `restore_file`: 续训，恢复完整训练状态（含 optimizer momentum）
5. **`finetune_from_model` + `reset_*` 互斥**——前者已隐含重置
6. **`task.target_dictionary` 需要 `+` 前缀**——base config 里没有这个字段
7. **数据路径用软链接修复**——比修改数据文件更可维护

### 两个 fairseq 实例

服务器上有两个 fairseq:
- `/root/asr-competition/fairseq/` — **训练用**（原始安装）
- `/root/asr-competition/submission/fairseq/` — 提交包（仅推理）

训练必须用前者，PYTHONPATH 必须指向前者。
