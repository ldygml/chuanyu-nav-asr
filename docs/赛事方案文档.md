# 赛事方案文档

## 川渝方言语音导航指令识别

---

## 一、赛题理解

### 1.1 任务描述

精准识别川渝方言环境下的语音导航指令，输入为川渝方言语音，输出为对应的文本转录。

### 1.2 导航指令特点

| 特点 | 示例 |
|------|------|
| 地名密集 | 什邡市方亭街道办、德阳实验小学淮河路校区 |
| 途经点 | 竹溪公园、石刻公园、华阳地铁站 |
| 路线偏好 | 城市快速路、避开限行 |
| 车辆需求 | 7座商务车 |
| 长句结构 | 单句包含出发地+目的地+途经+需求 |

### 1.3 挑战分析

| 挑战 | 影响 |
|------|------|
| 方言多样性 | 成都/重庆/乐山/自贡口音差异大 |
| 生僻地名 | 街道办、乡镇名不在常用词典 |
| 数字与量词 | 7座、9点、688号 |
| 语速变化 | 真实场景语速不均 |

## 二、技术方案

### 2.1 整体架构

```
输入: MFCC 特征 (T帧, 40维)
    ↓
Data2Vec 2.0 Encoder (0.3B)
├── Conv 特征前端 (40→512→512)
├── 相对位置编码
└── Transformer 12层 (768维, 12头)
    ↓
CTC 分类头 (768 → 7531)
    ↓
Viterbi 解码 → 文字输出
    ↓
normalize.py → CER 评测
```

### 2.2 基座模型选择

#### 候选模型对比

| 模型 | 参数 | 方言知识 | 选择 |
|------|:--:|------|:--:|
| large.pt | 0.3B | 仅预训练（无标注） | |
| finetune_large_kespeech.pt | 0.3B | 8方言微调（含川渝） | ✅ |

#### 选择理由

```
finetune_large_kespeech.pt 已学会方言→文字映射
→ 只需轻量适配导航场景
→ 避免从零学习方言发音
```

### 2.3 四大核心策略

#### 策略一：全模型微调

```
❌ 传统: 仅微调 Encoder，重建 CTC 头
✅ 本方案: 加载全模型（含 CTC 头），整体微调

原因: CTC 头的 7531 字映射知识同样宝贵
效果: 相比 encoder-only，CER 提升显著
```

#### 策略二：超低学习率（1e-06）

```
问题: 模型已有 30.7% CER 基础，大 LR 会破坏知识
方案: LR 1e-06（常规微调的 1/10）
效果: 只做微小方向调整，防止灾难性遗忘

学习率对比实验:
  LR 5e-06 → 通用赛道 7.08%
  LR 1e-06 → 通用赛道 5.50% ✅
```

#### 策略三：领域专用数据增强

```
方法: 速度扰动 (SoX tempo)
  原始 1.0x + 0.9x 慢速 + 1.1x 快速
效果: 数据量 3,385 → 13,240 (×4)
收益: CER 6.28% → 4.93% (-1.35pp)

选择理由:
  - 导航场景语速变化真实存在
  - 不引入通用数据干扰导航领域
```

#### 策略四：多段续训（Multi-Stage Fine-tuning）

```
核心思想: 从最优出发重新探索，跳出局部最优

阶段1: 基线 → 40k步 → CER 4.93%
阶段2: 40k最优 → 60k步 → CER 1.88%
阶段3: 60k最优 → 80k步 → CER 0.70%(训练集)

每段操作:
  checkpoint.finetune_from_model = 上段最优
  optimizer = 重新初始化
  LR scheduler = 从头开始
  LR = 1e-06 (保持)
```

## 三、实验结果

### 3.1 消融实验（导航 CER）

| 实验 | CER | 提升 |
|------|:--:|:--:|
| 基线（无微调） | 30.70% | — |
| + 纯导航微调（3.4k） | 6.28% | -24.42pp |
| + 数据增强（13.2k） | 4.93% | -1.35pp |
| + 二段续训（60k） | 1.88% | -3.05pp |
| + 三段续训（80k） | 1.10%* | -0.78pp |

\* 独立测试集（未参与训练的 300 条）结果

### 3.2 数据增强消融

| 配置 | CER |
|------|:--:|
| 无增强（3,385条） | 6.28% |
| 速度增强（13,240条） | 4.93% |
| 增强+3k通用（16k混合） | 4.46% |

### 3.3 通用数据影响实验

| 配置 | 导航 CER |
|------|:--:|
| 纯导航 13k | 4.93% |
| 3k通用 + 13k导航 | 4.46% |
| 35k通用 + 3.3k导航 | 10.04% |

**结论**：少量通用数据（~20%）略有帮助，大量通用数据稀释导航信号。

### 3.4 最终结果

### 独立测试集全对比（300 条未参与训练）

## 四、创新点

### 创新点 1：多段续训策略（Multi-Stage Fine-tuning）

```
传统: 单次训练到底
创新: 分段训练，每段从最优出发

技术细节:
  - finetune_from_model 加载完整权重
  - reset optimizer 重新探索
  - 极低 LR 保持已有知识
  - 3 段叠加: 4.93% → 1.88% → 0.70%

普适性: 适用于任何已收敛模型的继续优化
```

### 创新点 2：领域专用数据增强

```
创新: 面向导航场景的速度扰动
  - 0.9x / 1.1x 变速（不改变音高）
  - 纯导航增强，不引入通用干扰
  - 数据量 ×4，CER -1.35pp
```

### 创新点 3：全模型微调 + 超低学习率

```
创新: 保留 CTC 头方言知识
  - 相比 encoder-only 微调提升 2pp+
  - 1e-06 LR 精准适配
```

### 创新点 4：官方评测流程集成

```
创新: normalize.py + score.py 完整接入
  - 训练-推理-评测全流程自动化
  - CER 计算口径与官方一致
```

## 六、可复现性

### 6.1 复现步骤

```
1. 按环境配置文档安装依赖
2. 下载模型权重（finetune_large_kespeech.pt 等）
3. 准备数据（按自用数据集制作流程）
4. 运行 训练脚本/nav80k_cont续训.sh 训练（Stage1 nav80k + Stage2 续训 20k）
```
